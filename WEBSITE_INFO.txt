2. PROBLEM STATEMENT & OBJECTIVE
--------------------------------------------------------------------------------
On a bustling engineering college campus, valuable belongings are continually
misplaced: scientific calculators, hostel keys, wallets, water bottles, and ID
cards. Traditional campus notice boards and WhatsApp groups suffer from:
  1. Cluttered, unindexed feeds where lost posts vanish in chat history.
  2. Zero automated matching between finders and losers.
  3. False or mistaken claims due to lack of private ownership verification.
  4. Abandoned reports that linger forever without administration follow-up.

CampusFlix solves these pain points by actively connecting losers and finders:
  - Intelligently matching complementary reports using multi-factor scoring.
  - Enforcing compulsory photographic proof for found belongings.
  - Automatically alerting affected students and administrators.
  - Scheduling progressive reminders so unresolved cases receive continuous attention.
  - Protecting ownership through a private claim verification process.

4. INTELLIGENT LOST & FOUND MATCHING SYSTEM
--------------------------------------------------------------------------------
The core intelligent matching algorithm calculates compatibility between opposite
reports (Lost vs. Found) using a multi-factor weighted scoring formula:

   Factor                     Weight  Description
   --------------------------------------------------------------------------
   1. Item Name Similarity    35%     Token overlap, substring & bigram dice coeff
   2. Category Similarity     20%     Exact match = 100%, related family = 50%
   3. Description Similarity  20%     Stop-word filtered token Jaccard similarity
   4. Campus Location         15%     Landmark recognition (Library, Audi, Labs)
   5. Date Proximity          10%     <= 2 days = 100%, <= 5 days = 80%, etc.

Confidence Score Tiers:
   - 80% – 100% : Strong Potential Match (Prominent green banner & cards)
   - 60% – 79%  : Possible Match (Amber suggestion badge)
   - Below 60%  : Filtered out to avoid noise and false suggestions

Bi-Directional Discovery:
   - When a Found report is created, it compares against all Open Lost reports.
   - When a Lost report is created, it compares against all Open Found reports.
   - When typing in the report form, live suggestions update dynamically with
     a 300ms debounce to give students immediate feedback before submission.


5. MANDATORY IMAGE UPLOAD SYSTEM
--------------------------------------------------------------------------------
A. Lost Item Reporting (OPTIONAL):
   - Students reporting lost items can submit without a photograph.
   - Guidance message: "Adding an image can help others identify your missing
     item faster, but it is not mandatory."

B. Found Item Reporting (MANDATORY):
   - Photographic proof is strictly enforced on both frontend and backend.
   - Submission is rejected if an image is missing or invalid.
   - Guidance message: "Uploading a photograph is mandatory when reporting a
     found item. This helps the rightful owner identify their belongings."

C. Upload Capabilities:
   - Drag-and-drop file target + "Browse Files" button.
   - File format validation: JPG, JPEG, PNG, WEBP.
   - File size validation: Maximum 5 MB.
   - Animated upload progress bar with live percentage indicator.
   - Instant image preview with "Replace Image" and "Remove" controls.
   - Server-side disk storage in `server/uploads/` with unique timestamped hashes.

7. AUTOMATED UNRESOLVED LOST ITEM REMINDERS
--------------------------------------------------------------------------------
Lost belongings do not vanish or get neglected on CampusFlix. An automated
background cron scheduler checks unresolved Open Lost items across milestones:

   Milestone  Action & Delivery
   --------------------------------------------------------------------------
   DAY 1      Owner Reminder: "Your lost item is still marked as missing.
              No potential match has been confirmed yet. Report remains active."
   DAY 3      Owner Reminder + Campus Admin Alert: "Unresolved Lost Item Alert:
              A student is still waiting for their missing item. Please review."
   DAY 7      Owner Reminder + Admin High Priority Alert. The report is flagged
              with `needsAttention: true` and elevated in the Admin Dashboard.
   DAY 14     Final Scheduled Reminder to owner + Critical Alert to security
              desk for on-ground investigation. Report remains permanently active.

Rules & Safe Operation:
   - Reminders only trigger for `type: "Lost"` and `status: "Open"`.
   - Idempotent: `ReminderLog` checks prevent duplicate reminders for any milestone.
   - If an item is marked "Returned", all future reminders stop permanently.
   - Administrators can trigger instant manual reminders from their dashboard.


8. SECURE CLAIM CONFIRMATION & VERIFICATION WORKFLOW
--------------------------------------------------------------------------------
To prevent false claims and theft:
   1. The student clicks "Request Claim" on a found item.
   2. A secure modal prompts the claimant to describe PRIVATE identifying details
      that are NOT visible in public photos (e.g. secret stickers, scratches,
      serial numbers, wallet contents, keychain tags, lock combinations).
   3. The claim is stored with status `pending`.
   4. The person who found the item and Campus Security receive an instant alert.
   5. An authorized reviewer inspects the private answers in the Claim Review Modal.
   6. Upon verification, the claim is Approved and the student collects the item
      at the Campus Security Desk.
   7. The case is marked "Returned", concluding the case and notifying the owner.

10. COMPLETE REST API ENDPOINT REFERENCE
--------------------------------------------------------------------------------
Items:
   - GET    /api/items                     List items (filter by type, status, q)
   - GET    /api/items/:id                 Get specific item details
   - POST   /api/items                     Create report (Found image mandatory)
   - PUT    /api/items/:id                 Update item fields
   - PATCH  /api/items/:id/status          Update status (Open, Claimed, Returned)
   - DELETE /api/items/:id                 Delete report
   - POST   /api/items/upload-image        Upload JPG/PNG/WEBP (5MB limit)

Intelligent Matching:
   - GET    /api/matches/suggestions       Live autocomplete & potential matches
   - GET    /api/matches/item/:id          Calculated match candidates for an item
   - POST   /api/matches/recalculate       Batch recalculation of database matches

Notifications:
   - GET    /api/notifications             Get notifications for user
   - GET    /api/notifications/unread-count Get count of unread notifications
   - PATCH  /api/notifications/:id/read    Mark notification as read
   - PATCH  /api/notifications/read-all    Mark all notifications as read
   - DELETE /api/notifications/:id         Dismiss / delete notification

Claims & Verification:
   - POST   /api/claims                    Submit claim with verification details
   - GET    /api/claims                    List claims (role filtered)
   - PATCH  /api/claims/:id/status         Approve or reject claim

Reminders & Admin:
   - GET    /api/admin/reminders           List unresolved lost items with priority
   - POST   /api/admin/reminders/:itemId/send Trigger manual admin reminder
   - GET    /api/admin/reminders/history   Audit log of all reminder milestones
   - GET    /api/health                    API health & active feature manifest

Authentication:
   - POST   /api/auth/login                User login (Student or Admin)
   - POST   /api/auth/register             User registration
